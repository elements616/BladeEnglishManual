CAN Communication System

●
A CAN* [ISO11898] communication system, which transmits multiple items of information and data converted to digital signals by communication circuits over a pair of communication lines (twisted pair wiring), has been adopted. This reduces the wire harness and streamlines the electronic control systems connecting the input systems (sensors, switches, etc.), control units and output systems (motors, etc.).
HINT
*
CAN is an abbreviation for Controller Area Network, a serial communication conforming to ISO (International Organization for Standardization) standards.
●
The CAN communication system uses the 2 communication lines (bus), CAN High and CAN Low, as a pair, and determines the bus level* 1from their differential voltage; this is transmitted as a digital signal conforming to a dedicated communication protocol (communication rules) at a speed of 500kbps* 2(V bus) or 250kbps (MS bus).
HINT
*1
There are dominant and recessive bus levels; in the CAN communication system, dominant is logically judged as "0" and recessive as "1".
*2
A unit expressing signal transmission speed. "500kbps" indicates that 500000 bits of data are transmitted in 1 second(s).

CAN Communication Protocol (Communication Rules)


•
The CAN communication system is a time-division multiplex bidirectional communication system in which all computers (ECUs) and sensors that make up the network can both transmit and receive data at staggered times using a pair of communication lines (bus). Therefore, each ECU and sensor communicates in accordance with a common communication protocol (communication rules) so that communication is performed smoothly and reliably.
•
The CAN communication protocol adopts the CSMA/CD (Carrier Sense Multiple Access with Collision Detection) method* as the rule for sending data onto the communication lines, so that all ECUs and sensors can share a pair of communication lines while each has the right to start transmitting data.
HINT
*
Carrier Sense Multiple Access with Collision Detection: communication access control in which each ECU constantly senses the state of the communication line (carrier) and starts transmitting data only when no other data is flowing on the line. In addition, control in which, when a data collision (data transmitted simultaneously from another ECU) is detected, data is transmitted again after waiting for a fixed period of time.
•
Each ECU and sensor starts transmitting data when no other data is flowing on the CAN bus; when 2 or more ECUs or sensors start transmitting at the same time, the system determines the transmission priority according to the ID information contained in the transmitted data itself.
•
The data used in the CAN communication system consists of a frame made up of "ID", "DLC", "DATA", "CRC", "ACK", etc.


CAN Gateway Computer


•
To reduce the communication load between ECUs caused by the increase in ECUs in the CAN communication circuit due to increased functionality, a CAN gateway computer has been adopted and the CAN communication main line has been divided into 2 systems.
•
Highly important data from each ECU is set as a priority frame with a short delay time, reducing the data transmission delay within the gateway.
•
When the CAN gateway computer detects a malfunction in itself, it stops relaying data between buses to avoid transmitting incorrect data.

Related Parts


DLC3 (Data Link Connector No.3)

●
By connecting the diagnostic tool "TaSCAN" to the vehicle side connector (DLC3: Data Link Connector No.3), each ECU can be accessed via the gateway computer and the various multiplex communication lines. This allows output of DTCs, data monitoring (checking ECU data, etc.), Active Test (driving actuators as desired), customization (setting control programs), etc. For details, refer to the Repair Manual.
